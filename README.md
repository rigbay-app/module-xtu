# XTU profiles module for Rigbay

Switch Intel XTU power-limit profiles (PL1, PL2, time window) and read CPU temperature and power.

This is a module for [Rigbay](https://github.com/rigbay-app/rigbay), a Windows app that manages modules for your own machine.
Version 0.1.0. Early development: not released, no package published.

## Build

Needs Windows and the .NET SDK for `net10.0` or newer (the module targets `net10.0`). The host contract (`Rigbay.Abstractions`) comes from the
git submodule `external/rigbay`, so clone with submodules:

```powershell
git clone --recurse-submodules https://github.com/rigbay-app/module-xtu.git
cd module-xtu
dotnet build Rigbay.Xtu.slnx --configuration Release
dotnet test Rigbay.Xtu.slnx --configuration Release
```

The module folder is the build output of the module project (`Rigbay.Module.Xtu\bin\Release\net10.0`).

## Install into Rigbay

Rigbay reads modules from `%ProgramData%\Rigbay\modules\<id>\` (the folder name must equal the manifest id). Copy the whole build output
folder there, as `%ProgramData%\Rigbay\modules\xtu\`, with `module.json` at the top of that folder, then start Rigbay (as
administrator) and open the module page; the first time, the app lists what the module declares it uses and asks you to accept it.
`Rigbay.Abstractions.dll` must not be in the folder (the host ignores it and uses its own).

## What the module declares it uses

Administrator: True

Network:
- nothing

Registry:
- `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Power (HiberbootEnabled, read only)`
- `HKLM\HARDWARE\DESCRIPTION\System\CentralProcessor\0 (CPU vendor, read only)`
- `HKLM\SYSTEM\CurrentControlSet\Services\XTU3SERVICE (ImagePath, read only: to show the XTU version)`

Services:
- `XTU3SERVICE (named pipes net.pipe://localhost/ExtremeTuningUtility/Tuning and /Monitoring; writes only PL1, PL2, PL2 enable and the time window, after approval)`
- `reads C:\ProgramData\Intel\Intel Extreme Tuning Utility\Profiles.xml, uisettings.xml and xtu.hotkey.settings`
